# 核心升级恢复说明

恢复基线为 1.6.7 最后修订提交 `319f189267533a70707ab5165f790a4565c40a82`。
本次升级在 `upgrade/compose-export-core` 开发分支进行。

## 开发源码恢复

本地保留 `restore/1.6.7-319f189` 分支。切换前先停止应用、等待导出任务结束，并完成下文的“试卷中心缓存兼容整理”。工作目录干净时，执行：

```powershell
git switch restore/1.6.7-319f189
```

Git 会阻止覆盖冲突的未提交修改。先提交需要保留的工作，再切换分支；无需强制重置。
也可以在任意新目录解压仓库外的 `1.6.7升级前源码-319f189.zip`；同目录 `.sha256` 文件用于核对完整性。
该压缩包使用 `git -c core.autocrlf=false archive` 从基线提交导出，避免本机换行配置改变归档字节。
已使用源码核验工具逐文件比对 Git blob；核验结果在仓库外 `1.6.7恢复包核验.json`。
压缩包包含该提交跟踪的源码，不含本次开发改动。

## 试卷中心缓存兼容整理

新版可以读取工作区顶层的学科字段，1.6.7 的试卷中心只读取 `metadata.subject`，缺失时使用“通用”。如果直接切回旧版，旧版可能按另一学科键创建新记录，使教师列表暂时看不到原发布次数。原发布和答卷仍在，但这不满足可直接恢复使用的要求。

在停止应用后、切换源码前，从升级版代码根目录运行：

```powershell
# 只显示计划，不写入。
python -m tools.release_verify.rollback --project "实际教学内容目录" --platform-root "实际平台根目录"

# 整理旧版要读取的缓存键。
python -m tools.release_verify.rollback --project "实际教学内容目录" --platform-root "实际平台根目录" --apply
```

平台根目录指包含 `.solaire/platform.db` 的目录，不能误填成教学内容目录；两者应使用应用实际运行时的配置。若平台管理多个内容目录，应在停服期间逐一整理需要恢复使用的目录；输出中的 `skipped_missing_workspaces` 表示对应记录未在这次指定的内容目录找到，不能把它们记为已处理。

工具仅按 1.6.7 规则调整 `paper_records.subject` 缓存，不改变试卷 ID、归属、投放方式、文件夹、发布、答案或评分，也不改写试卷 YAML。多个同标识记录、归属冲突、非法路径或损坏元数据会使操作失败，整批不写入；工具不会合并或删除冲突记录。整理后立即启动旧版，停服期间不要再让新版同步缓存。若再次升级，新版会复用同一记录恢复新的学科显示。

该步骤是回退维护操作，不在新版普通运行期间自动执行。它不替代完整数据库和业务文件的常规运维恢复措施。

## 已合并改动的恢复

如果将来升级已合并，应依据实际合并提交执行 `git revert` 产生恢复提交，再运行原版回归并重新构建；保留已发布的历史记录。
具体提交范围以最终交付记录为准，不使用未经核对的批量重置或强推。

## 运行环境

开发过程不更新既有业务服务器，也不替换已发布的 1.6.7 安装包或标签。
源码包不含 Python / npm 依赖及运行产物；切回源码后须使用原来的依赖环境并重新构建前端。
线上代码回退使用保留的原安装版本；业务数据与账号应沿用原数据目录。
原 `EducationHelper-1.6.7-319f189267-linux-x86_64-offline.tar.gz` 已额外复核外包和内部散列、275 个应用源码及183 个已安装 Python 源码；结果为仓库外 `1.6.7原版离线包复核.json`。
本专项保持既有业务数据格式兼容。新增任务记录和本地草稿采用独立、带版本的存储，旧版可以忽略；试卷中心的学科缓存差异须在切回旧版前按上文整理。
