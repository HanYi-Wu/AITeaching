## 组卷、模板与文档导出

1. **统一网页与助手导出规则**：此前网页与助手分别处理 PDF、Word 导出的授权和恢复；现在共用执行流程与目标归属校验，减少入口之间的规则差异。
2. **导出失败保护已有文件**：此前导出中断可能覆盖旧文件或留下错误状态；现在先完整生成再替换，失败时恢复原文件及选题状态，保护已有试卷。
3. **并发导出保护共享编译文件**：此前并发任务可能同时修改同一项目的编译文件；现在同一项目的导出构建受线程与进程锁保护，减少并发导出冲突。
4. **导出任务持久保存**：此前导出进度依赖当前页面；现在保存任务状态并支持查询、中断核对和受控重试，减少刷新或断网后的重复提交。
5. **按账号、项目和试卷隔离本地草稿**：此前刷新或导出失败可能丢失未保存组卷编辑；现在浏览器可恢复按账号、项目、试卷隔离的草稿，刷新或导出失败后可继续编辑。
6. **切换身份或试卷后忽略旧请求**：此前账号、项目或试卷切换后的迟到请求仍可能写入当前页面；现在组卷请求有作用域保护，发布流程在保存失败或身份改变后停止，避免过期响应或错误身份继续影响当前操作。
7. **组卷工作区按职责拆分**：此前搜索、编辑、预览、侧栏及对话框集中在大型页面组件；现在组卷工作区由搜索、编辑、历史侧栏、预览、对话框等模块组成，便于按页面职责维护。
8. **组卷页续查和重试导出任务**：此前任务进度绑定页面生命周期；现在组卷页面提供导出状态、重新连接查询和手动重试，减少重复提交并保留失败恢复入口。
9. **读取历史成功任务不重复下载或清理草稿**：此前历史成功任务可能被当成新完成事件并重复触发副作用；现在历史成功任务只更新显示，当前运行任务完成后才处理结果，刷新页面不会重放旧任务副作用。
10. **长标签和题号不溢出相邻面板**：此前长英文标签、学科名与题号挤占相邻区域；现在组卷摘要、侧栏与题号在长文本下遵守面板边界，避免长文本挤压其他控件。
11. **校验导出压缩包并适配桌面保存**：此前下载内容未校验且仅通过普通浏览器链接保存；现在下载前检查 ZIP 签名并复用桌面兼容保存接口，减少错误文件下载并兼容桌面保存。
12. **返回组卷页时刷新知识点关联**：此前图谱修改后已挂载的组卷页仍显示旧关联；现在组卷页返回时刷新知识覆盖并忽略旧请求，无需刷新整个页面即可使用新绑定。
13. **修正 LaTeX 扩展版本识别**：此前版本横幅中的日期可能被误读为版本号；现在读取明确的版本字段，准确显示文档编译扩展版本。
14. **无效任务配置不再锁住重试**：此前失败任务的旧配置无法解析时，重试可能占用任务租约；现在先校验配置；无效时返回冲突并释放租约，任务保留失败状态，避免错误任务卡在队列或锁中。
15. **成功重试不删除后来修改的恢复草稿**：此前导出失败后继续编辑或产生产物的草稿可能在重试成功时被删；现在重试清理前复核内容指纹、状态、归属及产物，只删除未变化快照，保留用户在失败后新增的工作。
16. **组卷规则从界面提取为业务模型**：此前选题、移动、分值、数量约束和 API 序列化与页面状态交织；现在规则集中到独立模型并由页面协调调用，业务规则更容易单独核验和维护。
17. **组卷编辑增加有界撤销和重做**：此前编辑分值和选题后无法直接回到前一状态；现在保存有限历史并协调服务端保存基线，支持撤销和重做，可以恢复误操作且保护较新的编辑。
18. **启动导出后立即收起菜单**：此前选择 PDF/Word 导出后菜单仍保持展开；现在异步导出开始前即关闭相应菜单，页面能及时反映操作已启动并减少重复点击。
19. **拒绝零字节的成功文件响应**：此前HTTP 返回成功但响应体为空时仍可能打开预览或下载；现在检测空内容并给出错误，不向预览器或下载器传递空文件，减少无效文件和误判成功。
20. **模板预览和保存保护当前草稿**：此前切换模板或保存期间，旧预览和保存结果可能覆盖新模板编辑；现在按请求范围隔离模板数据，并在保存期间保留本地变更，教师编辑模板时不会被较慢的旧结果打断。
21. **组卷导出复用已校验内容和文档资源**：此前导出校验与编译重复解析题库和模板，教师版与学生版重复渲染相同题图；现在一次导出共享准备好的试卷输入，并在教师版和学生版之间复用同一题图资源，相同题库完整解析由2次降至1次，共享题图每次导出只渲染1次。
22. **修复 Word 试卷表格丢失**：此前紧邻正文或选项的表格可能在转换后丢失；现在正确保留内容边界，导出的 Word 试卷包含对应题目和表格。
23. **组卷搜索输入不重绘题目预览**：此前输入搜索词会带动未变化的题目预览更新；现在隔离搜索草稿，500 题样本中这类重复预览更新降至 0 次。
24. **表格转换只安全解析并展开一次**：此前表格转换重复解析输入和展开同一网格；现在采用安全 YAML 解析，并在一次转换中展开网格，5000格 LaTeX 转换约640ms降至113ms，OpenXML约638ms降至125ms，输出一致。
25. **拆分模板参数与字段政策编辑**：此前模板参数表单和动态字段规则集中在模板工作区中；现在抽出参数表单和字段策略，保留 字段配置、默认值和序列化规则，模板字段策略更容易维护，既有模板数据保持兼容。
26. **拆分组卷工作区路径和持久化适配**：此前工作区文档规范化、路径解析和持久化集中在组卷服务中；现在抽出身份、路径和持久化模块并复用原子写入与路径保护，组卷数据读写职责更清晰，既有失败恢复文件仍可读取。
27. **拆分组卷题库元数据与搜索筛选**：此前组卷工作区同时处理题库元数据、选择协调和搜索筛选；现在抽出高内聚的元数据和筛选边界，继续复用现有组卷模型，便于维护题库选择和搜索，不改变既有撤销、草稿和导出行为。
28. **拆分 Word 正文与题组内容构建**：此前Word题目正文、题组和小题的 Markdown 构建集中在同一编译流程；现在抽出正文渲染职责并保持教师版、学生版的题号、选项和答案顺序，Word正文和题组结构可独立维护及对照。
29. **拆分 Word 公式和媒体资源处理**：此前Word公式规范化、图片和图表物化与主编译流程耦合；现在抽出公式与媒体处理边界，并保留原资源路径、安全检查和错误信息，公式和媒体处理更易单独维护，导出资源继续使用原规则。
30. **拆分 Word 样式注入和转换执行边界**：此前引用样式处理和 文档转换 进程调用集中在文档编译模块；现在抽出样式注入与进程执行职责，并继续使用现有转换引擎和输出位置，便于维护转换配置与故障边界，保持原文档格式约定。
31. **模板版式字段跟随当前选择更新**：此前切换版式后，较慢返回的旧字段请求可能覆盖当前版式字段；现在仅接受仍属于当前模板和版式范围的字段响应，模板编辑器保持所选版式对应的字段。

## 题库、富文本与附件

32. **题库操作栏及时更新选题数量**：此前勾选或取消题目后操作栏可能仍显示旧数量；现在选择变化时同步刷新操作栏状态，导出数量与当前选择一致。
33. **题库连续编辑保存当前内容**：此前连续修改后保存可能提交旧内容或丢失附加信息；现在保存回调读取最新题目和附加信息，重新载入后保留最后一次编辑。
34. **集中题库文件夹移动规则**：此前文件夹树与移动判定散布在页面；现在独立建模并统一判断自身、后代和无效目标，保持移动规则一致。
35. **统一题组与单题选择身份**：此前题组和单题的选择判断与列表展示交织；现在用稳定编号统一维护选择集，减少筛选与折叠后的身份判定分歧。
36. **题库搜索响应跟随当前条件**：此前较慢的旧列表请求可能覆盖新筛选结果；现在读取状态按当前题库和请求代次更新，避免显示过期列表。
37. **分离题库操作栏与筛选展示**：此前操作栏、筛选展示和业务处理集中在题库页面；现在独立展示组件接收当前状态，降低按钮与筛选逻辑的维护耦合。
38. **题库网格框选不干扰文字编辑**：此前网格、列表和框选交互逻辑集中在题库工作区的同一实现中；现在抽出网格、列表和框选事件边界，并在监听器清理时保留原快捷键和文本编辑语义，题库视图交互更易单独维护。
39. **批量题库操作固定目标集**：此前请求进行中筛选改变或连续点击时，批处理目标可能漂移或重复执行；现在发起操作时冻结目标集，并协调重复触发和失败对象，批量操作结果与用户发起时看到的题目集合一致。
40. **题库批量结果与有效对象对齐**：此前对象已删除、文件夹已失效或部分操作失败时，列表可能错误移除题目；现在在移动、删除和导出前核验目标，并按服务端结果更新列表，让部分失败和无效目标可解释、可恢复。
41. **题目保存识别旧版本并保护新编辑**：此前题目在其他窗口更新后，旧窗口保存可能覆盖新内容；切题时旧详情也可能回填；现在保存时核对题目版本，保留旧客户端兼容，并阻止迟到详情覆盖当前草稿，减少题目内容被并发编辑或旧响应静默覆盖。
42. **统一公式编辑交互生命周期**：此前公式浮层、焦点和监听处理分散；现在统一管理挂载、切换与清理，保持公式输入和中文输入法交互稳定。
43. **题目图片上传不串入另一道题**：此前上传尚未完成时切换题目，旧上传响应可能写入新题草稿；现在按题目身份和编辑版本隔离图片上传回调，避免图片资源错误关联到另一道题。
44. **富文本异步插入保留当前内容**：此前公式或嵌入内容异步插入时，旧选区可能覆盖用户后续输入；现在提交前重新校验当前值和选区，避免迟到回调写回旧内容，公式、图片和文本连续编辑更可靠。
45. **编辑旧题库文件时保留其他记录**：此前旧版多记录题库文件更新一题时可能覆盖同文件的其他题目；现在按稳定题目身份更新目标记录，并以原子替换保留其余记录、组材料和扩展字段，降低旧题库编辑丢题和写入失败截断文件的风险。
46. **题库导入先验证全部内容再应用**：此前批量题库导入逐个写入时，末尾无效记录或中途写入失败可能留下未说明的部分结果；现在先校验题目、文件目标和图片关联，再按原策略应用并报告捕获的失败，减少部分导入和错误图片引用，并保留既有题目身份。
47. **题库选题导出建立一次索引**：此前每个导出目标都会重复扫描整库；现在每个文件只解析一次，导出 4 题、8 个文件的样本由 32 次解析降至 8 次，并省去无关图形渲染。
48. **公式编辑、PDF和助手界面按需载入**：此前尚未使用的助手、公式编辑器和PDF预览资源提前进入页面加载；现在在首次打开对应功能时再载入可选界面和引擎资源，减少初始加载需要处理的可选资源，同时保持首次使用能力。
49. **大文件窗口读取限制峰值内存**：此前只请求文本文件的小窗口也会先将整份文件读入并拆分；现在按窗口读取并保持原偏移和精确总行数语义，86MB文本窗口峰值内存由221449467字节降至441973字节，同时保留精确总行数。
50. **题库与组卷工作区读取复用安全数据**：此前题库目录和旧工作区加载重复解析 YAML 与工作区元数据；现在安全解析后复用同次请求的题库和工作区信息，230文件题库读取约288ms降至199ms，100个工作区加载约374ms降至127ms，返回摘要一致。
51. **编辑题目时侧栏预览保持稳定**：此前题目草稿变化会触发侧栏全部题目预览重复更新；现在将未改变的侧栏预览与正在编辑的草稿隔离，编辑一题时其他题目预览不再随草稿重复更新。
52. **抽出题库文件夹侧栏展示**：此前题库文件夹树和侧栏交互嵌在题库工作区主体中；现在将文件夹浏览和展示适配独立为侧栏组件，保留拖拽、折叠和鼠标操作，降低题库页面耦合并便于维护文件夹交互。
53. **拆分题目与题组编辑状态适配**：此前题目编辑状态类型和组件状态适配互相依赖大型编辑器组件；现在抽出类型和状态适配边界，保留旧类型导出及题型默认值，题目与题组状态可单独维护和核对。
54. **拆分公式符号面板和编辑浮层**：此前公式符号分类、插入和弹层界面与富文本编辑器主体混在一起；现在抽出符号面板和编辑浮层，并保留原符号、分类和快捷键，公式编辑界面更易维护且存储格式保持不变。
55. **拆分富文本 Markdown 与公式预览**：此前Markdown、公式和嵌入内容预览逻辑与编辑器主体耦合；现在抽出内容预览边界并复用原有渲染器和降级行为，便于维护多格式预览且保持既有公式和图表表现。
56. **限制表格附件输出缓冲内存**：此前大型表格附件的中间缓冲随单元格内容增长；现在限制输出缓冲并完整校验原范围，20 张工作表样本的峰值内存由 92.7MB 降至 0.96MB。
57. **图片占位符往返保留原始类别**：此前富文本解析图片占位符时会修改类别标记，保存再读取可能生成错误标记；现在解析、预览和序列化保留嵌入图片、图表和流程图占位符的原类别，题目内容往返编辑后仍可识别原图片和图形资源。
58. **隔离损坏题库文件并显示诊断**：此前无关损坏文件可能阻断已有健康题目的读取或保存；现在显示损坏文件诊断，允许已有健康题目继续读写并保护损坏目标，减少单个坏文件对正常编辑的影响。

## 考试发布、学生作答与教师批改

59. **试卷中心补全标签并保留试卷身份**：此前试卷中心显示路径和“通用”，纠正学科时可能产生新记录；现在显示真实标签和学科，补正元数据不改变试卷身份，可从原入口继续查看既有发布和答卷。
60. **发布去重仅撤销受影响的班级链接**：此前去重可能撤销无关的有效发布；现在去重仅撤销受重复班级链接影响的记录，降低无关发布被误改的风险。
61. **试卷发布名单一致保存**：此前并发或重复发布时，班级发布状态和答卷名单可能出现部分完成或重复记录；现在将发布对象校验与名单写入放在同一事务内，并复用已存在的有效发布，避免班级只收到部分试卷或重复生成有效答卷。
62. **为冻结试卷增加稳定内容标识**：此前已有冻结题目快照但缺少稳定内容标识；现在为快照生成可核对的身份，便于草稿恢复和后续读取确认题目来源。
63. **分离答案批次校验与保存协调**：此前答案批次校验、保存和交卷逻辑交织；现在独立处理有界批次并保留原事务规则，便于验证并发保存和交卷顺序。
64. **拒绝非有限批改分数**：此前非有限数值可能进入评分存储并污染统计；现在保存前拒绝无穷值等无效分数，保持成绩计算和汇总有效。
65. **批改单题分数与总分同步提交**：此前逐题分数保存后，答卷总分可能暂时仍显示旧值；现在把题目分数、答卷总分和完成状态放入一致事务提交，避免教师和学生看到彼此不一致的成绩。
66. **识别过期批改版本**：此前多个教师窗口编辑同一答卷时，较旧内容可能覆盖新评分；现在批改页面可附带当前答卷版本，服务端识别过期写入，同时兼容旧请求，减少并发批改时无提示覆盖已保存内容。
67. **成绩发布一致性**：此前未完成批改或重复完成请求可能造成发布状态与成绩不一致；现在发布前核验全部批改状态，并以幂等方式处理重复请求，避免未完成成绩对外可见或重复改变成绩。
68. **保留批改中的分数与评语草稿**：此前刷新或迟到的读取结果可能把空分、零分和已编辑评语混为一类；现在独立管理分数、评语草稿和脏状态，并在刷新后保留未提交编辑，教师可以更可靠地继续未完成的批改。
69. **保护较新的批改编辑**：此前连续切卷或连续保存时，旧请求可能覆盖当前评分字段；现在按答卷、题目和版本串行协调保存，并拒绝过期字段更新，防止迟到响应覆盖教师更新的评分和评语。
70. **批改草稿按账号和答卷隔离恢复**：此前离开批改页或遇到中断后，未提交的评分草稿可能丢失或串到其他答卷；现在保存有范围的本地批改草稿，并检查源版本后再恢复，教师可以在账号、项目和答卷间安全地续做批改。
71. **恢复学生文字作答草稿**：此前未确认保存的文字作答在刷新后难以恢复；现在按账号、项目、答卷和冻结题目保存本地草稿并核对来源，便于中断后继续作答。
72. **本地恢复图片作答草稿**：此前图片草稿依赖当前页面；现在使用容量受限的本地图片存储并明确提示保存失败，减少刷新后的丢失和误判已保存。
73. **分离学生考试流程与作答面板**：此前考试计时、保存、提交和展示集中在页面；现在由独立流程模块协调并拆分作答面板，降低状态衔接的维护难度。
74. **图片确认时保留文字答案**：此前确认图片作答时，当前题目文字内容可能被一并清空；现在修复图片确认与文字答案之间的状态处理，并补齐完整流程回归，学生确认图片后仍可保留已输入的文字答案。
75. **试卷列表只接收当前筛选结果**：此前较慢的旧筛选请求可能覆盖新列表；现在按查询代次保护列表与分页，保留用户当前选择的筛选结果。
76. **学生成绩页及时显示教师新发布的成绩**：此前学生停留在成绩页时，教师后来发布的成绩不会及时出现；现在沿用现有刷新机制同步新成绩，并保留逐题详情筛选状态，学生无需重新打开页面也能看到已发布结果。
77. **拆分试卷记录存储与可见性查询**：此前试卷记录复用和可见范围查询集中在同一服务中；现在抽出记录仓储和可见性策略，旧服务入口继续兼容，减少查询与持久化职责耦合，并保留原发布、答卷和文件夹关联。
78. **集中试卷发布生命周期规则**：此前发布时间、状态转换和发布方式校验散落在试卷服务路径中；现在抽出生命周期政策，旧暂停、恢复、关闭和撤回入口继续使用同一规则，让发布状态校验保持一致且便于维护。
79. **拆分学生考试会话和服务端计时**：此前学生领卷资格、考试会话和时间窗口处理集中在学生服务中；现在抽出考试会话与计时职责，仍由服务端裁定考试时间并复用既有答卷，便于单独维护领卷与计时规则，同时保持旧答卷身份和答案保护。
80. **统一预批改与 OCR 建议适配边界**：此前AI和OCR建议结果与教师最终评分路径紧密相连；现在抽出预批改适配器并校验预算、超时和建议结果，失败仍不写教师最终分，保持人工评分权威并便于替换或维护建议处理逻辑。
81. **拆分教师答卷查询和学生画像读取**：此前教师答卷列表、范围过滤和学生画像读取集中在试卷服务中；现在按查询职责提取模块并统一稳定排序和范围过滤，便于维护分页和授权边界，不改变教师原有可见范围。
82. **拆分试卷接口模型与领域路由**：此前试卷接口输入模型和领域路由集中在同一 API 文件中；现在将路由与输入模型分层，并保留旧导入入口和原 参数结构 名称，降低接口维护耦合且维持已有客户端兼容。
83. **拆分试卷列表与发布面板**：此前试卷列表、发布侧栏和班级发布表单共用一个工作区组件；现在按职责提取列表与发布面板，并保持原选择、时间设置和发布入口，试卷工作区更易维护且旧发布操作保持一致。
84. **拆分批改工作区和答卷详情视图**：此前教师批改主工作区同时承载答卷列表、详情和评分展示；现在抽出批改工作区与答卷详情组件，保留原评分和发布顺序，批改界面职责更清晰，同时维持现有操作路径。
85. **批改分数变化不重绘固定题目内容**：此前教师输入分数时，每道未变化题目的富文本也随整页更新；现在固定题目内容与分数草稿分离，分数输入只更新必要区域，250题批改场景下富文本重复更新由1500次降至0次，输入和题目内容保持一致。
86. **学生成绩行显示答卷记录的班级**：此前学生成绩行可能显示当前发布的全部目标班级，而非该答卷实际记录的班级；现在成绩行按答卷保存的班级视图显示，并保留冻结未知的空值和转班历史，教师可按作答时真实可见的班级理解历史成绩，不会把新班级套到旧答卷。
87. **监考事件按答卷身份筛选班级**：此前按班级筛选监考记录时可能使用事件自身标识而非对应答卷标识；现在使用监考事件关联的答卷身份进行班级匹配，正确显示该班级答卷的监考记录，且不扩大教师或学校的数据范围。
88. **缩小试卷页面定时更新范围**：此前闲置发布面板的计时会触发整页更新；现在将周期变化限制在需要更新的区域，减少闲置页面的无关渲染。

## 复练与学情分析

89. **复练与诊断批次及实际答卷建立稳定关联**：此前复练草稿、诊断批次和真实发布答卷之间缺少稳定来源标识；现在通过稳定身份关联分析批次、工作区草稿、发布与答卷，教师能确认复练结果属于哪一批诊断和哪份真实答卷。
90. **复练发布时冻结知识点基线**：此前首考成绩和题目绑定之后变化时，复练前值可能被悄悄改写；现在在发布事务内冻结来源成绩、知识点和计算规则版本，前后对照保留可追溯且一致的基准。
91. **按配对证据计算知识点掌握度**：此前缺少稳定的复练知识点前后对照规则；现在按知识点等比分摊题目得分与满分并比较配对样本，避免缺失作答被当作零分。
92. **复练对照处理重批和来源变化**：此前首考重批或来源内容改变后，对照可能沿用过期值或重复累计；现在保持冻结基线，并按允许展示的最新成绩重新判断对照有效性，教师和学生看到的增量与当前有效数据一致。
93. **学习进步数据按角色授权读取**：此前教师或学生缺少稳定的只读入口，可能需要从其他接口拼接对照信息；现在新增教师与学生范围受限的学习进步读取接口，教师只查看获授权学生，学生只查看本人且不泄露未发布分数。
94. **教师分析页显示知识点前后对照**：此前教师需要在多个页面间切换才能核对复练前后的知识点变化；现在在现有分析位置展示前值、后值、增量、样本量与缺失原因，教师可在原工作流内解释班级和学生进步证据。
95. **学生成绩页显示本人复练对照**：此前学生难以在成绩详情中查看本人复练前后的知识点变化；现在在既有成绩详情展示个人对照，并区分无基线和未完成，学生能够理解自己的前后变化而不会把缺失值误读为零分。
96. **旧分析记录缺失来源时标为不可比较**：此前历史批次或题目身份缺失时，系统可能无法区分真实提升与无法关联；现在兼容旧记录、读取来源摘要并在身份不可靠时标记不可比较，避免为缺少可靠来源的数据生成虚假提升结果。
97. **成绩分析共享同一冻结数据快照**：此前多个报表分别重复读取同一冻结题目和答案，班级总计也可能来自不同时间点；现在在同一请求内复用冻结题目、答案和读快照，并统一统计版本读取，题目、答案、统计和班级总计在同一请求中使用一致的冻结输入，避免跨时点汇总。
98. **成绩统计缓存随计分输入失效**：此前修改题目满分后，旧缓存仍可能返回先前的分数比例；现在缓存身份包含实际计分输入，旧版、不完整或无效缓存会重新计算，成绩统计与当前题目分值匹配，写入失败也不会破坏旧缓存。
99. **复练发布复用同一批来源数据**：此前复练发布按学生重复读取图谱和答卷来源；现在一次发布共享只读图谱输入并成批读取来源答案，同时保留来源摘要规则，两学生场景下图谱入口由5次降至1次、来源查询由10次降至4次。
100. **班级复练对照按学生分组聚合证据**：此前班级前后对照重复逐条处理大批知识点证据；现在按学生集中聚合配对证据，并保持原始计算精度和缺失样本规则，144000条双侧证据计算由929ms降至211ms，200组随机差分结果一致。
101. **成绩工作簿写入时同步计算列宽**：此前生成成绩工作簿后还需再次读取大量单元格以计算列宽；现在边写行边计算列宽并写出工作簿，1200名学生、100题的完整构造和保存由4876ms降至3419ms，单元格和样式一致。
102. **成绩统计复用题目列与聚合索引**：此前成绩统计在同一数据集内重复寻找题目列并重算节点汇总；现在复用题目列头和节点聚合索引，保留排序、舍入和计算指纹，1200名学生、100题完整统计由约313ms降至219ms。
103. **拆分成绩文件定位、批次和统计职责**：此前成绩文件查找、导入批次和统计计算集中在成绩服务；现在提取文件位置、批次和统计边界，沿用原成绩模板和身份匹配规则，便于维护成绩读取和统计，避免按姓名猜测学生身份。
104. **拆分自适应练习生成和发布规则**：此前来源校验、选题、生成校验和发布集中在自适应练习服务中；现在按策略、选题、生成和发布职责拆分模块并保留原资格与题目校验，复练规则更容易维护，既有历史资格和内容有效性要求保持。
105. **拆分分析批次选择和结果面板**：此前分析工作区同时管理批次选择、诊断状态和多个结果面板；现在提取批次选择、诊断状态和结果视图，切换后隔离旧请求，分析页面职责更清晰且保留脚本、诊断和补练草稿入口。
106. **补齐诊断到复练成绩对照的端到端回归**：此前诊断、人工复核、复练提交和前后对照缺少同一可重复的集成验收入口；现在增加贯穿真实 API 和角色隔离的完整工作流回归，后续修改能验证首考、复练和成绩对照的整条数据关系。
107. **分析结果跟随当前账号和项目范围**：此前账号、项目或权限切换时，较慢的旧分析响应可能回填当前页面；现在按当前账号和项目范围丢弃迟到结果，并阻止旧范围继续发起诊断操作，避免展示或操作另一个项目中的分析结果。
108. **分析复用证据并限制报告读取范围**：此前分析会重复转换证据并读取无关班级数据；现在复用证据且限制读取范围，组合优化后 1,200 人、12 万答案样本由 1,643ms 降至 644ms。
109. **拆分试卷分析与统计计算模块**：此前试卷分析报告、题目统计和班级聚合计算集中在试卷服务中；现在抽出分析与统计职责，并保持缺考、未提交和未发布成绩的原统计口径，分析计算可以独立维护和逐字段核对，不改变既有成绩含义。

## 学校、账号与登录

110. **初始化管理员退出后直接显示登录页**：此前首次建立管理员后退出可能返回初始化页；现在管理员初始化状态与登录状态同步，避免误提示再次初始化。
111. **集中学校账号生命周期处理**：此前账号创建、禁用和密码重置规则分散；现在集中处理生命周期与事务边界，便于一致维护学校账号规则。
112. **统一花名册身份与关联规则**：此前班级成员和教学分配的身份判断散布在不同入口；现在集中身份与唯一性规则，保持重复导入和改名后的既有关系。
113. **学校导入先校验再提交**：此前学校导入的校验和写入协调分散；现在先核验整批数据再按事务规则提交，明确错误行并减少半完成导入。
114. **执行时复核学校 AI 权限**：此前旧会话或后台工作可能沿用已失效的学校 AI 设置；现在在实际执行前重新确认学校策略和当前管理权限，关闭 AI 后，旧请求不能绕过当前设置继续执行。
115. **学校批量状态更新返回逐项结果**：此前批量启用或停用只返回匹配数，管理员难以区分每个账号的实际变化；现在对每个账号返回实际状态迁移结果，并保持原批量政策，管理员能定位成功、未变化和未匹配对象。
116. **消除普通浏览器登录前的额外等待**：此前普通浏览器也会等待桌面连接探测；现在直接连接服务，快速响应样本的登录可用中位数由 5,048ms 降至 42.7ms。
117. **临时认证故障保留可重试会话**：此前认证请求遇到网络或服务器错误时会清除有效会话；现在仅在明确未授权时失效，短暂故障后可以重试连接。
118. **学校学生列表按页读取并复用班级关系**：此前大型学校列表请求重复查询关联数据，响应随数据量明显变慢；现在使用保持原搜索语义的分页聚合和学生班级索引，导入时批量查重，5000名学生空搜索第一页中位数由825.032ms降至16.431ms，宽命中由826.763ms降至20.812ms。
119. **学生转班采用学校管理员明确操作**：此前普通导入可能隐式改变学生班级，历史多班记录也无法安全判断当前归属；现在普通导入只校验不转班，学校管理员通过独立预览和确认完成转班并保留历史身份，防止误转班，同时保留账号、答卷和成绩关联。
120. **拆分学校组织和数据范围查询**：此前学校、班级关系读取和不同角色数据范围查询集中在学校服务中；现在抽出组织关系与范围查询模块，沿用原管理员、教师和平台管理员权限，学校数据范围规则更易维护且不扩大既有访问权限。
121. **拆分学校接口模型与路由**：此前学校账号、班级、组织和 AI 设置接口集中在单一路由文件；现在按领域拆分 参数结构 和路由，同时保留原路由注册与请求响应结构，接口职责更清楚，旧客户端和文件下载约定保持兼容。
122. **拆分学校管理数据与面板**：此前学校页面同时承担数据读取、账号管理、导入和任课展示；现在拆分数据协调与管理面板，降低页面维护耦合。
123. **拆分平台会话存储和认证状态适配**：此前平台会话键、旧令牌清理和认证状态转换分散在认证页面逻辑中；现在抽出会话存储与认证适配器，保留全局会话键、清理和退出行为，账号切换和旧会话清理规则集中维护，同时继续支持已有入口。
124. **拆分平台领域 API 和共享类型**：此前多个领域 API 和共享类型集中在认证客户端外观中；现在按领域提取 API 与类型，并保留旧命名导出供现有调用使用，降低客户端文件耦合且无需整体改写已有调用。
125. **退出或切换账号后丢弃旧认证响应**：此前退出和切换账号后迟到的认证响应可能恢复旧状态；现在只接受当前登录轮次的认证结果，保持退出和账号切换后的身份正确。

## 知识图谱与交互

126. **图谱批量变更先完整校验再一致写入**：此前并发修改或后半段校验失败时，关系和节点文件可能只保存一部分；现在复用项目级写入协调，先校验整批节点和关系，再串行写入并处理捕获的失败，降低图谱丢更新、半份保存及重复关系的风险。
127. **切换图谱节点后忽略旧详情响应**：此前切换节点后，旧笔记或关联详情的迟到读取可能回填当前面板；现在按活动节点隔离读取结果，保护新节点的编辑内容。
128. **图谱布局复用节点位置索引**：此前图谱力布局逐节点线性查找坐标，节点越多重复工作越多；现在为布局计算维护节点位置索引并减少关系键分配，256节点布局由约788ms降至378ms，坐标逐位一致。
129. **拆分图谱仓储和迁移模块**：此前图谱服务同时处理模型、缓存、路径、仓储和旧状态迁移；现在按领域拆出仓储模块并沿用原 YAML 格式、节点身份和迁移结果，图谱存储职责更清晰且既有图谱文件继续可读。
130. **图谱输入只更新当前编辑节点**：此前在大型思维导图输入草稿时，无关节点组件也重复更新；现在输入更新只触发活动编辑器及必要的图数据变化，500节点场景下每键自定义节点更新由501个降至1个。
131. **迟到的图谱改名结果保留新草稿**：此前较早节点改名请求完成时可能关闭或覆盖用户正在编辑的新草稿；现在仅让仍匹配当前节点和编辑轮次的改名结果更新状态，保护快速连续编辑中尚未提交的节点名称和笔记。
132. **拆分图谱节点编辑面板职责**：此前图谱节点编辑、文件、笔记和题目关联都集中在单一面板组件；现在按编辑、文件、笔记和题目关联拆分面板，同时保留原操作与焦点行为，图谱节点面板职责更清晰，后续交互调整影响范围更小。

## 助手与任务状态

133. **助手请求遵循网络设置**：此前助手请求可能被系统环境中的转发设置干扰；现在遵循应用按域名配置的网络策略，减少错误转发和连接超时。
134. **助手能力注册前校验参数契约**：此前能力名称重复、处理器缺失或参数结构不匹配可能延迟到运行时才暴露；现在注册时核验能力目录、处理器和参数契约，同时保持原选取顺序，降低助手调用错误能力或以错误参数执行的风险。
135. **助手多步操作逐次核验权限**：此前等待确认期间发生的权限变化可能未及时生效；现在恢复执行及每个步骤前重新核验权限，阻止已不再授权的操作。
136. **助手失败恢复区分可安全重试操作**：此前网络中断后重放写操作可能重复发布、批改或修改数据；现在将失败分类并限制重试与取消在安全边界内生效，降低中断后重复写入和状态误报。
137. **助手流式结果按调用身份去重**：此前重复或迟到的能力事件可能在对话中重复生成能力卡片；现在以能力调用身份归并消息、附件和卡片，保持流式顺序并避免对话结果重复展示。
138. **提供持久且按所有者隔离的任务状态**：此前导出、分析和助手任务的状态分散，刷新或重启后难以解释当前进度；现在持久保存任务身份、来源、范围、尝试次数和有限进度，用户可在同一权限范围内查询任务进度和中断原因。
139. **导出任务接入统一进度查询**：此前导出任务状态只在原服务中可见，工作区无法统一呈现；现在把已有导出任务映射到统一状态视图并保留原任务 ID 和入口，用户可以查看导出进度，同时旧查询和重试方式保持可用。
140. **分析任务接入统一进度查询**：此前分析任务状态与其他长任务分散展示；现在将现有分析任务生命周期映射到统一状态视图，不重复启动分析，用户可查询分析任务进度且原结果入口保持兼容。
141. **关联助手回合与操作步骤状态**：此前助手回合和各步骤缺少统一状态关联；现在按原任务记录关联并隔离会话权限，便于断线后核对进度及防止重复写入。
142. **预批改可在后台受控运行**：此前耗时预批改只能依赖同步操作，权限变化和人工批改版本难以在后台统一核验；现在新增兼容的异步入口，并在运行前复核权限、学校策略和人工批改版本，教师可以查询预批改进度，同时旧同步接口仍可使用。
143. **统一任务查询并保留来源约束**：此前跨类型任务缺少统一且受来源约束的查询入口；现在统一读取任务状态，重试仍由原业务服务复核权限，减少越权和重复执行。
144. **工作区接入统一任务查询**：此前组卷页使用导出专用状态读取；现在复用跨任务查询模块核对来源状态，统一重连和权限范围处理。
145. **文档和 OCR 内容绑定前再次校验**：此前从文档或 OCR 提取的内容可能在进入题库或图谱前缺少完整边界校验；现在沿用现有解析和确认流程，在写入题库或绑定图谱前强化输入校验，减少无效或未确认内容污染题库和图谱。
146. **助手上下文只统计需要的考试记录**：此前构造助手上下文时会读取不必要的成绩目录内容；现在按需统计考试记录，并在读取时复用当前对话所需的数据，20场考试、14.5万行CSV输入下，上下文构建由68.6434ms降至6.4196ms且输出一致。
147. **任务状态读取不等待后台写事务**：此前任务状态查询在后台写事务期间会等待数据库锁；现在读取路径不再额外获取写锁，同时保留旧数据修复规则，250ms写事务期间读取由约258ms降至约1.8ms。
148. **减少长会话历史长度重复计算**：此前长会话整理会反复计算未变化的历史消息；现在复用计数，500 轮样本由 13,191ms 降至 80ms，并保持最终输入一致。
149. **增量组装助手流式参数**：此前每个流式片段到达时都会重建整段参数；现在按片段增量组装并在完成时校验，40KB 参数样本由 39.88ms 降至 19.80ms。
150. **按领域拆分助手能力参数定义**：此前助手能力参数 参数结构 集中在一个定义模块；现在按题库、组卷、批改、图谱、分析和基础能力拆分 参数结构，能力参数更易维护，同时保持103项既有名称、描述、默认值和风险标记。
151. **拆分教师和考试能力处理适配器**：此前教师和考试能力处理器混在大型能力模块中；现在按教师内容、批改、图谱、发布和导出职责拆分适配器，便于维护能力与领域服务的连接，并保留原权限和确认策略。
152. **拆分助手流式事件分发和终态处理**：此前流式事件解析和终态清理集中在助手编排器中；现在抽出事件分发与终态生命周期模块，保留旧事件名、正文、顺序和心跳，降低流式处理耦合并维持已有客户端兼容。
153. **补齐长任务中断和重复确认故障回归**：此前任务中断、重复事件、取消和权限变化缺少同一故障验收用例；现在增加重启、重复确认和来源恢复边界的可重复故障回归，能验证完成产物不会因取消回退，未知写入不会被盲目重放。
154. **拆分助手对话消息和能力卡片面板**：此前助手对话、消息渲染、能力卡片和附件展示集中在单一面板组件；现在按消息、附件、卡片和会话职责拆分组件并沿用原流式行为，对话界面更易维护，同时保持滚动、确认和附件展示操作。

## 架构、数据安全与交付

155. **请求身份与业务接口分离**：此前请求身份、权限上下文和业务接口集中耦合；现在按业务拆分接口并在请求结束时恢复上下文，减少模块依赖和身份串扰。
156. **统一应用初始化**：此前启动入口同时承担初始化与接口注册；现在由独立应用工厂统一装配，原有服务与桌面入口继续可用。
157. **公开部署隔离项目草稿**：此前公开部署缺少不暴露路径的稳定草稿标识；现在以公开项目标识区分草稿，兼顾恢复能力和服务器路径保护。
158. **校验源码、运行文件与前端产物对应**：此前交付可能混入不同版本的运行文件或旧前端产物；现在逐项校验源码、安装入口及前端输入输出来源，拒绝内容错配。
159. **补齐接口与权限兼容检查**：此前嵌套端点和试卷权限缺少集中契约覆盖；现在核对旧路径、请求响应、角色范围及重复注册，降低接口和权限回归风险。
160. **规范化 Windows 扩展路径后再校验边界**：此前扩展盘符和 UNC 路径命名空间差异会干扰目录包含关系判断；现在Windows 扩展路径在项目目录边界比较前被规范化，减少路径别名绕过目录校验的风险。
161. **工作区保存核验归属并保持原子性**：此前嵌套工作区写入及既有试卷更新的路径/归属校验不一致；现在工作区创建和更新核对归属并使用原子文件写入，失败不留半成品且既有归属受到保护。
162. **回退维护保留试卷、发布和答卷关联**：此前新版学科字段回退后可能被旧版识别为“通用”并生成重复草稿；现在回退维护可按旧版读取规则整理缓存而不改变业务记录身份，降低回退后列表与发布/答卷关联分离的风险。
163. **清理遮蔽实现并检查代码完整性**：此前重复实现可能遮蔽有效逻辑，未定义名称也可能漏检；现在清理无效实现并检查重复定义和未定义引用，减少基础代码错误。
164. **数据库迁移按版本执行**：此前普通请求会重复执行结构迁移和历史修复；现在只在版本变化时迁移，教师列表样本的数据库语句由 436 次降至 10 次。
165. **按需加载助手运行依赖**：此前后端启动时提前载入暂未使用的助手依赖；现在首次调用时再载入，应用导入样本由约 2,571ms 降至 1,257ms。
166. **减少离线运行文件的重复副本**：此前离线运行目录包含重复应用文件与未使用静态归档；现在保留单份应用及必要依赖和入口，降低包体积并保持原有能力。
167. **事务结束及时释放数据库连接**：此前事务提交或回滚后连接可能仍短时占用数据库文件；现在明确关闭自有连接并保留借用连接的控制权，减少文件占用。
168. **拆分 API 地址解析和传输适配**：此前API 地址、桌面连接等待、网络错误解析和下载传输逻辑混合在客户端中；现在抽出地址解析和传输边界，同时保留 表单上传、下载与原错误语义，便于分别维护浏览器和桌面连接路径，不盲目重试写请求。
169. **构建失败立即停止打包**：此前Windows 前端构建命令失败后可能继续使用旧产物；现在构建失败立即返回错误并终止后续打包，避免失败构建被误当作成功交付。
170. **修复离线安装后的源码导入路径**：此前运行目录布局与相对路径处理可能导致安装搬迁后无法导入应用；现在依据实际应用位置定位导入根并正确保留相对路径，保持安装、更新和失败恢复后的应用可用性。
