# 组卷与 API 核心升级设计和验证

基线：1.6.7，`319f189267533a70707ab5165f790a4565c40a82`。

## 目标和范围

第一阶段覆盖组卷前端、后端入口与路由、网页与智能体导出边界，以及交付核验。采用模块化单体，保留现有桌面、本地、公开部署方式。迁移职责、编写业务模型、交付新能力和修复缺陷分别说明，不能用移动文件或提交数量代替功能与质量证据。

## 后端边界

- `app.py` 保留原 ASGI 入口；`application.py` 创建应用，`routing.py` 注册业务路由。
- `request_context.py` 负责访问控制、发起人及图谱请求上下文，并在请求完成后恢复上下文。
- 业务路由和输入模型按项目、系统、题库、模板、图谱、分析、试卷划分；业务服务不反向依赖路由或应用入口。
- `export_workflow.py` 统一 PDF / Word 的授权、目标解析、共享构建、异常恢复和成功清理。
- `export_policy.py` 同时用于网页和智能体；编译前授权目标、状态更新和清理目标，编译后重新检查归属。
- `export_lock.py` 通过线程锁和操作系统锁保护项目共享编译文件；不同项目互不阻塞。
- `export_tasks.py` 持久化状态和稳定请求标识，检查账号权限、队列容量、进程中断与手动重试。该队列用于单机持久任务，不承担跨机器调度。
- `export_cleanup.py` 对失败草稿记录内容指纹，并在删除前核对状态、产物、归属及修订；已保存的新工作保留。

## 组卷边界

- `composeModel.ts` 是选题、批量移动、分值、数量约束、模板同步和 API 序列化的纯业务模型。
- `composeHistory.ts` 管理有界撤销与重做；`useComposePaperHistory.ts` 协调历史、服务端保存基线和本地恢复。导出期间的新编辑不会被旧提交的完成事件覆盖。
- `composeDraftStorage.ts` 只保存允许的试卷字段，按账号、项目和试卷隔离，显式选择恢复或丢弃；身份不明、存储不可用或配额不足时降级提示。
- 公开模式继续隐藏服务器路径。`/api/project/info` 增加不含路径的稳定 `project_id`；项目副本在其他目录获得不同作用域，本地模式沿用既有路径键。
- `useComposeRequestScope.ts` 丢弃账号、项目、试卷切换和卸载之后的迟到响应。
- `useComposeExportTasks.ts` 管理提交、轮询、断网后继续查询、幂等重交和当前试卷任务恢复；历史失败不会污染新试卷的清理列表。
- `useComposePublishing.ts` 管理线上发布流程；保存失败或身份改变后停止后续写入。
- 侧栏、题库检索、试卷编辑、预览和对话框分为界面组件，工作区协调业务流程。

## 存储及恢复兼容

未迁移原有业务数据库。新增 `.solaire/export-tasks.sqlite3`、锁标识、项目标识及带版本的浏览器草稿；失败草稿的可选元数据用于保护自动清理。旧版可忽略这些新增信息。

回退前等待正在执行的导出结束，切回保留的 1.6.7 源码或原安装包并重新构建前端。具体步骤见[恢复说明](../core-upgrade-recovery.md)。原标签和发布包保持不变。
