# 管理员运维与 Linux 升级设计

## 目标

修复管理员页面的平台 AI 配置、页面布局和扩展组件安装流程，并提供可校验、可回滚、保留数据的 Linux 一键升级入口。实施严格分为本地修复与远端发布两阶段。

## 根因

- 公网访问中间件把 AI 设置写入和全部扩展变更都归为“主机控制”，要求浏览器无法提供的本机控制令牌，导致管理员登录后仍被拒绝。
- 管理员页面把 AI、学校账号和扩展管理固定放入 440px 右栏，宽屏下形成拥挤的纵向堆叠。
- 扩展自动安装仅支持 Windows winget；Linux 服务进程无法安全地交互式提权，页面却没有给出可执行的替代路径。
- 现有部署脚本适合首次安装，缺少稳定的 latest 清单、校验、健康检查和失败回滚语义。

## 设计

### 权限边界

新增“管理员配置”权限层：AI 设置、安全模式、提示词覆盖和扩展首选路径只要求已登录管理员，不再要求本机控制令牌。教师、学校和学生仍返回 403。项目目录选择、脚本执行等真正的主机控制操作继续要求管理员和控制令牌。

扩展自动安装属于主机变更：Windows 仅允许管理员在界面明确确认后启动 winget；Linux 不从 Web 服务执行 sudo，而是返回可复制的系统安装命令，安装完成后由管理员重新检测。

### AI 配置

保存后重新读取有效配置，展示实际生效的供应商、主模型和脱敏密钥状态。新增管理员专用连接测试接口，使用当前有效配置发送最小请求，返回是否成功、模型、耗时和脱敏错误，不把 API 密钥返回浏览器。

### 管理员页面

保留首次使用清单，主体改为全宽分区导航：学校与账号、平台 AI、扩展组件。每个分区独立滚动和布局；创建表单只在学校分区内并排，AI 与扩展区域使用可读宽度，不再固定在右栏。

### Linux 升级

发布 `latest-linux.json` 和 `upgrade-linux.sh`。升级脚本下载并校验发布包，解压到版本化 release 目录，保留 `/var/lib/educationhelper` 与 `/etc/educationhelper`，切换 current 链接并重启服务；健康检查失败时恢复旧链接并重启。脚本支持 `EH_INSTALL_PROXY_URL`，允许重复执行。

## 验收

- 公网模式下管理员可保存并回读 AI 设置，非管理员不能写入。
- AI 连接测试能区分成功、未配置和供应商错误。
- 管理员三类工作区在桌面和窄屏均不挤在固定右栏。
- Windows 显示确认式安装，Linux 显示安装命令且不会假装已安装。
- 本地后端、前端定向测试和构建通过后，才生成 1.5.1 发布包并更新下载站。
- Linux 升级脚本具备校验、数据保留、健康检查和回滚测试。
