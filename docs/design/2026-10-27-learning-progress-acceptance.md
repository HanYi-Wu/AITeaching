# 学校管理与复练对照验收

学校组织、账号、花名册和导入入口保留原有接口与稳定身份。整校文件中的班级、教师、学生和任课导入共用事务，后段失败会回滚整批数据。AI 审核后的实际导入在写入事务内重新核对学校状态和 AI 开关。

复练通过发布 ID、答卷 ID 和学生 ID 关联来源。发布事务冻结首考得分、知识点分摊规则和题目绑定；首考复核只标记来源变化，复练重批读取当前成绩。缺失来源不作为零分。学生对照与原成绩详情使用同一个完成批改标记，教师查询按已分发学生和任教范围过滤。

教师在原诊断位置选择关联复练即可查看对照，无需输入内部标识。前后得分率、配对人数和题数使用相同样本；未完成、未批改和未发布分别展示，未配对学生不进入汇总。

可重复的真实 API 验收入口：

```text
python -m pytest tests/test_learning_progress_workflow_acceptance.py -q
```

使用合成学校、教师、学生、题库与图谱，通过现有公开接口完成首考发布、学生作答、人工复核、历史错题复练、复练提交、批改和成绩发布。实际验证：首考 2/4、复练 3/4 显示 50% → 75%、增加 25 个百分点；另一学生未完成时不参与配对均值。另验证源成绩复核、复练重批、发布后修改图谱绑定及跨教师、学校和学生的访问限制。

相关回归覆盖学校整批回滚、审核期间关闭 AI、共享发布的教师范围、未分发新成员、旧记录与来源删除、前端迟到响应及接口字段匹配。完整后端、前端、构建、源码归档和 Rust 检查沿用现有 CI。
